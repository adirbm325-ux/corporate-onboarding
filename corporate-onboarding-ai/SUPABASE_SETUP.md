# הקמת Supabase — Checkpoint 3A

האפליקציה עובדת מצוין גם בלי לעשות שום דבר מהמדריך הזה — היא תמשיך
לשמור הכל ב-localStorage בדפדפן, בדיוק כפי שעשתה עד כה. המדריך הזה
מיועד רק למי שרוצה לחבר בסיס נתונים אמיתי בענן.

## שלב 1 — יצירת פרויקט ב-Supabase

1. הירשמו/התחברו ל-[supabase.com](https://supabase.com) וצרו פרויקט חדש (חינמי).
2. המתינו כדקה-שתיים עד שהפרויקט עולה.

## שלב 2 — הרצת הסכמה

1. בתפריט הצד: **SQL Editor**.
2. לחצו **New query**.
3. פתחו את הקובץ `schema.sql` שבשורש הפרויקט הזה, העתיקו את כל התוכן, הדביקו ב-SQL Editor.
4. לחצו **Run**. אמורות להיווצר 7 טבלאות: `branch_settings`, `cases`, `people`, `couriers`, `forms`, `tasks`, `activity`.

## שלב 3 — קבלת המפתחות

1. בתפריט הצד: **Project Settings → API**.
2. העתיקו את **Project URL** ואת **anon public key**.

## שלב 4 — הגדרת משתני הסביבה

1. בשורש הפרויקט, העתיקו את `.env.example` לקובץ חדש בשם `.env`:
   ```
   cp .env.example .env
   ```
2. פתחו את `.env` ומלאו:
   ```
   VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```
3. שמרו את הקובץ.

## שלב 5 — הרצה

```
npm install
npm run dev
```

פתחו את האפליקציה, עברו למסך **"הגדרות חיבור"** בסרגל הצד — כרטיס "בסיס נתונים" אמור להראות **"מחובר ל-Supabase"** תוך שנייה-שתיים מעליית הדף. אם הוא מראה **"עובד במצב מקומי"**, בדקו:
- שהערכים ב-`.env` הועתקו נכון בלי רווחים מיותרים.
- שהפעלתם מחדש את `npm run dev` אחרי עריכת `.env` (Vite קורא משתני סביבה רק בעלייה).
- שהרצתם בהצלחה את `schema.sql` (בלי שגיאות ב-SQL Editor).

## מה קורה בפועל

- **טעינה ראשונית תמיד קורית מ-localStorage** — מיידית, לא תלויה ברשת.
- אם ה-localStorage ריק לגמרי (דפדפן/מכשיר חדש) והחיבור ל-Supabase תקין, האפליקציה תנסה למשוך נתונים קיימים מהענן ברקע.
- **כל שינוי** (פתיחת תיק, מילוי טופס, שינוי סטטוס) נשמר קודם ל-localStorage באופן מיידי, ואז מסונכרן ברקע ל-Supabase אם יש חיבור.
- אם החיבור ל-Supabase נופל בכל שלב (רשת, מפתחות שגויים, שרת לא זמין) — האפליקציה עוברת אוטומטית בחזרה למצב מקומי, בלי הודעת שגיאה למשתמש ובלי לאבד נתונים.

## הערת אבטחה חשובה

מדיניות ה-RLS ב-`schema.sql` היא **"demo allow all"** — פתוחה לחלוטין, כי עדיין אין באפליקציה אימות משתמשים אמיתי (מתוכנן ל-Checkpoint 3B). **אין להזין נתונים אמיתיים** של לקוחות/תאגידים לפרויקט Supabase בשלב הזה.
