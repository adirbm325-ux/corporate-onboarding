# מדריך הרצה — Corporate Onboarding AI (פיילוט)

## אפשרות 1 — הרצה מקומית במחשב של העסק (הכי מהיר להתחיל)

### דרישות
- Node.js גרסה 18 ומעלה מותקן במחשב ([nodejs.org](https://nodejs.org))

### הרצה
1. חלצו את קובץ ה-ZIP לתיקייה כלשהי במחשב.
2. פתחו טרמינל/שורת פקודה בתוך התיקייה שנוצרה.
3. הריצו פעם אחת:
   ```
   npm install
   ```
4. בכל פעם שרוצים להפעיל את האפליקציה:
   ```
   npm run dev
   ```
5. יופיע קישור כמו `http://localhost:5173` — פתחו אותו בדפדפן.

**חשוב לדעת:** במצב הזה כל הנתונים נשמרים בדפדפן המחשב הספציפי הזה בלבד (localStorage). אם עוברים למחשב אחר או דפדפן אחר, לא רואים את אותם הנתונים. זה מתאים לפיילוט על מחשב אחד/עמדה אחת. אם רוצים שכמה עמדות/משתמשים יראו את אותם נתונים, צריך לחבר את Supabase (ראו `SUPABASE_SETUP.md`) — וגם אז שווה לזכור: אין עדיין התחברות משתמשים אמיתית (מתוכנן לשלב הבא), אז כל מי שניגש לקישור רואה ועורך את אותם הנתונים.

### לסגירת האפליקציה
`Ctrl+C` בטרמינל שבו הרצתם `npm run dev`.

## חשוב מאוד — שליחת קישור ללקוח דורשת פרסום בענן (אפשרות 2)

כל תיק כולל כפתור **"שלח קישור ללקוח"**, שמכין הודעת WhatsApp/SMS/מייל מוכנה עם קישור אישי לתיק. **הקישור הזה מבוסס על הכתובת הנוכחית שבה האפליקציה רצה בזמן שנוצר.**

- אם מריצים **מקומית** (`npm run dev`, אפשרות 1), הקישור יהיה `http://localhost:5173/...` — כתובת שתקפה **רק על המחשב הזה עצמו**. לקוח שילחץ עליה מהטלפון שלו לא יגיע לשום מקום.
- כדי שקישור שנשלח ללקוח באמת יעבוד מהטלפון שלו, **האפליקציה חייבת לרוץ בכתובת ציבורית** — כלומר יש לפרסם אותה בענן (אפשרות 2 למטה, Vercel/Netlify) לפני שמתחילים לשלוח קישורים ללקוחות אמיתיים.

## אפשרות 2 — פרסום בענן (Vercel) — נגיש מכל מקום בלינק אחד

מתאים אם רוצים שכמה אנשים בעסק ניגשים לאותו קישור בלי להתקין כלום אצל כל אחד.

1. העלו את תיקיית הפרויקט (בלי `node_modules`) ל-GitHub, כרפוזיטורי חדש.
2. היכנסו ל-[vercel.com](https://vercel.com) והתחברו עם חשבון GitHub.
3. **Add New → Project**, בחרו את הרפוזיטורי שיצרתם.
4. Vercel מזהה אוטומטית שזה פרויקט Vite — משאירים את ההגדרות כברירת מחדל.
5. אם חיברתם Supabase: לפני הלחיצה על Deploy, תחת **Environment Variables** הוסיפו:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   (בדיוק כמו ב-`.env` המקומי שלכם — ראו `SUPABASE_SETUP.md`)
6. לחצו **Deploy**. תוך דקה-שתיים תקבלו קישור קבוע כמו `your-app.vercel.app`.

### Netlify — אותו רעיון בדיוק
1. אותו רפוזיטורי ב-GitHub.
2. [netlify.com](https://netlify.com) → **Add new site → Import an existing project**.
3. Build command: `npm run build`, Publish directory: `dist`.
4. אם יש Supabase — הוסיפו את שני משתני הסביבה תחת **Site settings → Environment variables**.
5. **Deploy site**.

**עדכון עתידי:** בכל פעם ששולחים שינוי (`git push`) לרפוזיטורי, גם Vercel וגם Netlify מפרסמים אוטומטית גרסה מעודכנת — אין צורך לחזור על תהליך ההעלאה.

## תזכורת אבטחה חשובה לפני כל פרסום בענן
כרגע אין באפליקציה התחברות משתמשים אמיתית ואין הפרדת הרשאות אמיתית — כל מי שיש לו את הקישור רואה ועורך הכל. **אין להזין נתוני לקוחות אמיתיים** בשלב הזה, ואם מפרסמים בענן — מומלץ להגביל את הגישה לקישור (למשל Vercel Password Protection בתוכנית בתשלום, או פשוט לא לשתף את הקישור מעבר לצוות הפנימי). אותה הערה חלה גם על קישורי "שלח ללקוח" הספציפיים לתיק — הם לא מוצפנים ואין להם תוקף פג, ולכן יש לשלוח אותם רק ללקוח המיועד ולא לשתף אותם בפומבי.
